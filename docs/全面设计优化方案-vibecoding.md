# 小雪项目 · 全面设计优化方案（vibecoding 体验重构）

> 作者：小白 | 2026-08-19
> 定位：这是**全面设计层面的优化蓝图**，不是零碎改动清单。它把小雪从「一套要你记入口、记流程、催你确认的工具」重新设计成「**一本会说话的笔记本**」——你只管说、做、想，剩下的让系统自己对齐。
> 前置：本方案覆盖《总体设计》「骨架 + 可组合能力 + 小雪自主选择」目标，并把被延期的「前端查看/管理体验」从设计上接进来。它不改产品目标和安全边界，只把**流程与体验设计**理顺。

---

## 0. 一句话主轴（这版全面设计的核心）

> **小雪 = 一本会说话的笔记本。**
> 你往里说一句话，它就知道记到哪页、跟哪页关联、什么时候该提醒你；
> 你想看什么，翻一页就能看到，想改什么，说了就能改；
> 它自己记住怎么找、怎么回，你不用记任何入口、命令或流程。

一切设计都朝这一句话收敛。凡是让"你记、你催、你找、你重复"的设计，都是要砍掉的宿主。

---

## 1. 从设计上消灭你的 4 个痛点（根因，不是补丁）

你最近的痛，本质都是**同一根主轴断了**：你想的、它存的、你看到的、你改的——不是同一个东西，还散了多处。设计上这样根治：

| 你的痛点 | 根因 | 全面设计解法 |
|---|---|---|
| **① 想看的翻不到**（版本理解在前端没有） | 内容存在哪、展示在哪、调用在哪，是三处 | **单一正源，处处可见**：每个对象只有一个家（如版本理解=数据库一条记录），所有页面、所有 Skill、所有入口都只从这一个家读。前端不再有"藏着的内容"。 |
| **② 想改的没入口 / 被门禁卡** | 写入逻辑是"检测证据→拦你" | **你拍板就写**：识别到是你在确认一个对象的内容，就直接写那个对象并读回；证据只当提示、不当闸门。把"反复要你确认"删掉。 |
| **③ 改了不知道生效没** | 没有"落盘反馈" | **每个对象自带"身份证"**：显示它来自哪、什么时候更新的、当前状态。你在前端看到的就是唯一事实，不会再猜。 |
| **④ 概念散乱、要重复讲** | 同样的东西起了好几个名、放了好几个地方 | **统一命名 + 统一家谱**：版本理解/画像/TK/市场记录，每个只有一套名、一个家、一份说明。memory-bank 接进前端，你打开就知道项目全貌。 |

---

## 2. 全面设计的四层

小雪不是一堆功能页，是一套**从"你"到"数据"的完整链路**。每层都按 vibecoding 体验重新设计：

```
第1层 你（自然语言，什么都不用学）
  ↓ 说一句话
第2层 小雪（理解 → 自主选择能力 → 组织回答）
  ↓
第3层 能力/对象（每个都是一个闭环：可进→可读→可改→可回看）
  ↓
第4层 数据与记忆（单一正源 + 身份证 + 冲突并列）
```

### 第1层 · 你 —— 自然使用，零学习成本
- 你永远只说人话：聊聊某队、看看版本、记一笔、改一下、翻翻以前。
- **不加暗号**：不说"执行/调用/打开/继续"这些词，小雪也能懂。
- **不问工具名**：你不需要知道"赛程表叫 ts-table、笔记叫 TK、盘口叫 market-notes"。

### 第2层 · 小雪 —— 自己会选、会组合
- 一套公共骨架：**自然进入 → 读唯一正源 → 需要时写 → 写后读回**。
- 小雪自己决定要不要组合多个能力（比如"明天 HLE 打 GENG 怎么看"→ 它自己拼赛程+队伍+版本+交易方法）。
- **不强制流水线**：它不是每次都让你走完八步。能直接答就答。

### 第3层 · 能力/对象 —— 每个对象闭环、可见、可改
这一层是前端体验的骨架。每个"对象"（队伍画像/版本理解/TK/当前比赛/盘口记录）都长一个样：
- **状态卡**：这个对象现在什么样（有内容/缺数据/有冲突/过期？）
- **身份证**：来自哪个正源、什么时候更新的
- **看**：展开就是全部内容，从单一来源读
- **改**：你说"改它"，就是改这个正源，改完读回给你看
- **回看**：以前的东西都在，按时间能翻

> 设计上消灭"前后端脱节"：前端页面不再有自己的一套"展示逻辑"，它只负责把**正源对象**呈现出来 + 把**你的自然语言改动作**送回去。

### 第4层 · 数据与记忆 —— 单一事实源，不造假
- **只有一个家**（你已经认可的方向）：版本理解只有数据库一条，队伍只有一份画像，判断只有交易记录。
- **冲突并列显示**，绝不好心替你合并。
- **缺数据就说缺**，不装懂、不编造。

## 3. 前端界面全面设计

既然是"全面设计优化"，前端不能只是"把后端内容显示出来"的壳，它要是**你日常翻看这本笔记本的界面**。重新设计为三个层面：

### 3.1 全局：一整本笔记本，不是一堆按钮
把现在相互独立的页面（队伍资料/当前赛事/TK/盘口/项目中心）统一成一个**有导航的笔记本**，导航本身按"你接下来想干嘛"组织，而不是按技术模块：

- **"现在看什么"**（当前赛事 / 焦点比赛 / 今天）
- **"长期记的"**（队伍画像 / 版本理解 / 知识 TK / 交易记录）
- **"刚改过 / 待确认"**（最近改动 / 冲突条目 / 待沉淀）
- **"项目本身"**（开发进度 / 模块说明 / 说明书 —— 原项目中心）

导航栏你自己不用记，小雪会按语境带你去；但你想自己点也点得清楚。

### 3.2 对象层：每个对象一张「卡片」，四段统一
任何对象（队伍/版本/比赛/TK/记录）展开都是同一结构：
```
标题（统一命名）            [身份证：来自哪 · 何时更新 · 状态]
├─ 当前内容（唯一正源全文，可展开）
├─ 冲突/缺口（有哪些待确认、缺什么）
├─ 相关（关联了哪些别的对象：比赛↔版本↔队伍）
└─ 操作（改它 → 说给小雪；复制 → 给别处；沉淀 → 变成长期）
```

### 3.3 交互层：**说 = 动作**
- 前端那条"你想改什么"的输入，不是技术表单，是**一句自然语言**（"把这版本更新成钦定""BLG 的需改成…"）。
- 小雪收到后：确认对象 → 写入正源 → 读回 → 把改后的卡片展示给你。**全程你不用知道表名、字段、API**。

## 4. 开发/迭代流程的全面设计（vibecoding 的本质）

vibecoding 的真正敌人不是"代码复杂"，是**每次改动之间你对"现在什么样"失去把握**。所以设计的重心：**每个对象 + 每个改动都有可见的、可回看的"痕迹"**。

### 4.1 融入 memory-bank（已有，但要让它在前端可见）
- memory-bank 已经是一套好的 vibecoding 底座（README/progress/modules/loop）。
- **设计升级**：把 `progress.md` 变成前端"最近改动"那一栏的数据源。你打开工作台就看到"上次做了什么、现在到哪了"，不用问。

### 4.2 一个对象一个闭环，改完必反馈
- 每次变化（无论是你改、小雪改、还是 cron 自动更新）都留痕迹：**改了什么、来源、时间、状态**。
- 前端展示"最近变化"，你随时知道系统在动什么、动了哪里。**改A炸B 能被直接看见**（在哪次改动、哪个模块）。

### 4.3 loop 的默认化
- 把 vibe-coding 的 loop 从"你主动说 loop"变成**默认节奏**：小雪每次完成一个对象操作，都自带"改了什么 + 你怎么验证 + 结果"；你验证 ✅ 它更新 progress；❌ 它只修你指出的地方。

---

## 5. 落地顺序（全面设计，但分阶段落地）

全面设计不等于一次性全部重写。按「先让主轴通、再谈界面美」分四阶段：

| 阶段 | 做什么 | 完成标准 |
|---|---|---|
| **P0 主轴打通** | 先保证"每个对象单一正源 + 前端看得到 + 你拍板能改"在核心对象（版本理解、队伍画像）上成立 | 你在前端看到户型，说出改动，读回生效 |
| **P1 对象卡统一** | 所有对象统一成"状态卡 + 身份证 + 看/改/回看"结构 | 任何对象展开都是同一套卡 |
| **P2 界面美化** | 笔记本导航 + 对象卡视觉重做 | 打开就像翻一本清晰的笔记本 |
| **P3 痕迹/loop 可见** | 最近改动栏 + 自动 loop 汇报 | 随时知道系统动了哪、改A不炸B |

---

## 6. 边界（本方案不做什么）

- **不改产品目标和安全边界**：不替钧钧自动交易、不伪造数据、冲突仍并列、高风险动作仍确认。
- **不动飞书主路径**：手机飞书仍是正式入口，"前端可见/可改"是补充查看与管理界面，不是替代聊天。
- **不在设计阶段就动手改代码**：本方案是蓝图，逐阶段施工前再分别对齐和验收。
- **保持单一事实源**：版本理解、画像、TK 的单一正源不变，只统一"从哪读、怎么展示、怎么改"。

---

## 结语

这版全面设计把整套系统收敛成一个主轴：**小雪是你会说话的笔记本，你在前面说、做、想，它在后面把每一页对齐、标日期、让你看得见、改得动、回得了。** 任何让你"记入口、催流程、翻半天找不到、改了不知道有没有生效"的设计，都在这个设计里被消灭。
