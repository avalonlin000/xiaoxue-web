# CS2 业务指导

> 层级：项目。本文件维护 CS2 的使用目标、默认展示、判断含义、资料边界和验收依据。共同规则见根 [AGENTS.md](../../AGENTS.md)；当前能力和缺口以 [项目合同](../../config/project-contract.json)、[模块合同](../../config/module-contract.json) 为准。

## 1. 用户要什么

CS2 用于围绕钧钧点名的赛事、地图、队伍、选手或市场问题，快速找回已有依据并讨论当前判断。用户要的是先回答眼前问题、说明资料适用条件，再把历史认识与今天的事实分开；不是看到一张假装完整的实时工作台。

系统帮助查回专项方法、普通 TK、交易 TK 和原文，整理地图、阵容状态、赛程、市场及结果中的可用部分；钧钧决定信息是否足以支持本场判断。

## 2. 怎样使用

用户可以直接问某场比赛、某张地图、某支队伍、某个盘口或回合数问题，无需选择固定流程。系统先确认对象和时间范围，再优先读取与该问题直接相关的正式材料。

讨论已形成的认识时，查回原文、来源、时间和适用条件；讨论本场时，单独核对当前赛事、阵容、地图和价格。要把方法、历史材料与实时事实组合时，才按需读取多个来源。

记录和复盘沿用项目现有 TK 与单场能力；普通讨论不会自动生成长期 CS2 结论。

## 3. 先展示什么

先直接回答当前问题，并说明依据来自哪个时间、哪场比赛或哪种资料。涉及本场时，优先区分：已核实本场事实、历史材料、系统推导和仍待核实项。

涉及地图、选手状态、赛程、盘口或结果时，清楚显示已覆盖与缺失部分。已有方法与 TK 只展示与当前问题相关的内容，不把整个知识库铺成默认答案。

涉及价格时必须同时说明时间与来源；历史赔率不能作为实时报价。对本场适用性没有证据时，明确说明不能直接套用历史结论。

## 4. 怎样判断

历史认识可以说明过去在何种赛事、地图、队伍状态或市场条件下成立；它不自动证明今天的本场条件相同。系统推导必须能回到事实或原文，钧钧的明确判断和限制优先于通用方法。

地图与阵容因素要落到具体地图、选人和时间点；盘口与回合数问题要区分赛前公开信息、当时价格和赛后结果。资料冲突或时点时，并列保留差异及影响。

项目当前不承诺完整实时工作台，因此“查不到当前资料”不能由 LOL 页面、历史材料或模型记忆补齐，也不能把部分能力说成整条链路已可用。

## 5. 资料和能力边界

- 已有部分知识、交易 TK、专项讨论方法和原文检索能力；地图、选手状态、赛程、盘口和结果源覆盖不完整。
- TK 是材料或钧钧判断，不自动升级为当前事实；普通讨论不暗中写入长期知识。
- 来源缺失或过期时说明影响；明确要求实时或外部核对时，才走当前只读外部检索入口。
- 不把其他游戏页面、接口或赛果当作 CS2 能力，不编造赛程、阵容、地图、价格和盘口。
- 不自动下单或把讨论包装成已执行交易。

## 6. 怎样验收

| 场景 | 用户应看到的结果 |
|---|---|
| 查回一条已有认识 | 给出原文或正式材料、来源、时间及适用条件 |
| 讨论本场适用性 | 明确哪些是已核实本场事实，哪些只是历史材料或待核实内容 |
| 讨论盘口或回合数 | 价格标明时间与来源，不用旧赔率冒充当前报价 |
| 缺少关键本场资料 | 说明具体缺口和影响，不把历史材料包装成当场事实 |
| 查看可用入口 | 只展示 CS2 已有能力，不用 LOL 当前赛事或结果链补成 CS2 入口 |
| 普通讨论 | 不发生长期 TK、画像、交易结论或状态的自动写入 |
