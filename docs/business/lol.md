# 英雄联盟业务指导

> 层级：项目。本文件维护 LOL 的使用目标、默认展示、判断含义、资料边界和验收依据。共同规则见根 [AGENTS.md](../../AGENTS.md)；接口、字段、配置和能力状态仍以 [项目合同](../../config/project-contract.json)、[模块合同](../../config/module-contract.json) 及正式方法 Skill 为准。

## 1. 用户要什么

钧钧用 LOL 能力完成五类事情：查队伍资料、准备一场比赛、分析纯十英雄阵容、讨论交易方法、记录和复盘。目标是在当前问题上更快拿到可靠材料，由钧钧决定本场重点、方法取舍和最终交易判断，而不是被要求走固定流水线或把所有模块都看一遍。

系统负责整理事实、找回已有 TK 和方法、补充必要的推导并说明缺口；系统不替钧钧选主要矛盾，不把分析结果自动变成下注指令，也不因为一次讨论就改写长期画像、版本理解或 TK。

## 2. 怎样使用

常见场景可以直接从当前问题开始：

- 只查队伍时，问五项画像、首发或某个明确队伍事实；只返回所问内容。
- 赛前准备时，指定比赛，先整理本场已有可靠信息、未确认项、暂缺项和少量相关方法；钧钧指出关注点后继续深入。
- 纯阵容分析时，提供蓝红方各位置十个英雄；只分析阵容结构和比赛观赛信号，不扩查队伍、赛果、TS、TK、盘口或新闻。
- 讨论交易时，明确说明要把哪些事实、市场、趋势、分歧或风险放在一起；系统再按需读取对应模块。
- 记录或复盘时，说明要保存、修正或查找的 TK、单场观察或赛果；写入后从同一正源读回。

用户改变方向时，沿用当前对象和上下文继续，不要求重述已有的本场资料。缺少比赛身份或回答会因此改变时才问一个关键问题。

## 3. 先展示什么

用户只问队伍画像、首发或队伍资料时，只展示五项画像和明确请求的队伍事实；不自动读取或附加 TS、TK、盘口，以及 volatility/trend 等内部字段。只有用户明确要求组合时，才读取并展示对应模块。TS 只有被明确要求时才按五个固定中文名称展示，不输出英文键、速度/加速度、波动度、原始量或历史数列。

赛前首屏先排本场已有事实，再区分已确认、未确认和暂缺；方法提示保持少量、相关、可追溯，把本场主要关注点留给钧钧。纯十英雄分析先给出输入边界和阵容结构，再说明阶段路线、控制与反制及观赛信号；交易讨论才补充市场、队伍和方法证据。

## 4. 怎样判断

事实、系统推导和钧钧判断必须分开表达。事实注明对象、时间和来源；推导说明依据及可能被哪些变化推翻；钧钧已有的方法、重点和结论优先于系统默认方向。资料冲突时并列来源、时间、差异和影响，不静默融合成一个结论。

纯十英雄结论只代表阵容范围内的判断，不等同于完整比赛或交易判断。“赛前值得关注”不自动变成“现在交易”。普通 TK 是知识与方法材料，交易 TK 是带适用条件、交易含义和失效条件的认识；两者都不自动升级为画像、当前判断或赛果。

## 5. 资料和能力边界

- 画像是当前长期结论；TS、首发、版本和赛果是会变化的事实；TK 是材料或钧钧判断。它们各自从正式来源读取，不互相自动改写。
- 普通讨论、临时观点和单场结果不会自动进入长期知识；明确要求保存时，沿现有 TK 或单场正源写入并读回。
- 数据缺失时显示缺哪一项及其对回答的影响；来源失败时明确“读取不完整”，不编造已读取内容。
- 当前赛事、日报、自动化和完整对话复盘仍有独立状态，不能因某个页面或接口可用就宣称全链路稳定。
- 数值、版本、队伍名单和字段不复制到本指导维护；以配置、合同、代码和正式方法为准。

现有实现入口可从 [技术导航](../architecture/PROJECT-MAP.md) 定位。赛前交互的业务要求参考已实施但真实多轮入口尚未验收的[赛前专项记录](../archive/designs/赛前方法引导与主要矛盾判断-PRD.md)；该未完成事实继续以进度和交付证据为准。

## 6. 怎样验收

| 场景 | 用户应看到的结果 |
|---|---|
| 已有资料后在当前对话继续 | 不要求重述系统已能读取的比赛、队伍或上下文资料 |
| 用户改变关注点 | 沿同一场比赛和当前材料切换，不重跑固定清单或强迫逐项回答 |
| 只查画像、首发或队伍资料 | 只有五项画像和明确请求的事实，没有自动扩查 TS、TK、盘口或内部字段 |
| 纯十英雄输入不完整 | 只在真正缺英雄或位置歧义时澄清，不用队伍资料补猜 |
| 资料不足或来源失败 | 说明具体缺口和可继续回答的部分，不编造事实或方法使用史 |
| 普通赛前讨论 | 不发生画像、版本、TK 或交易 TK 的暗中写入或状态修改 |
| 明确要求保存 | 沿正式入口写入，并从同一正源读回 |

验收至少经过当前接入助手的真实多轮入口。合同测试、页面能打开或单个接口成功只证明局部条件，不能代替真实使用路径。
