# 无畏契约业务指导

> 层级：项目。本文件维护无畏契约的使用目标、默认展示、判断含义、资料边界和验收依据。共同规则见根 [AGENTS.md](../../AGENTS.md)；当前能力和缺口以 [项目合同](../../config/project-contract.json)、[模块合同](../../config/module-contract.json) 为准。

## 1. 用户要什么

无畏契约用于围绕钧钧点名的比赛、队伍、地图、阵容或市场问题，查回已有专项方法与 TK，并判断一条认识能否用于当前场景。用户要的是可追溯的依据和清楚的适用条件，不是把已有页面当成完整实时工作台。

系统负责找回材料、区分历史与本场事实、指出缺口；钧钧决定本场主次和使用哪些方法，并承担最终判断。

## 2. 怎样使用

用户可以直接提出一个具体问题，不必先选择模式。系统先识别对象、赛事、时间范围和问题类型，再读取最相关的专项讨论材料、普通 TK、交易 TK 或原文。

查一条已有认识时，说明它来自哪里、当时何时、适用什么版本、地图、队伍和阵容条件。讨论本场时，另查当前比赛、地图、阵容和价格；只有明确要求组合时，才将历史材料与当场事实放在一起。

普通讨论和临时判断不会自动成为长期 TK；明确要求保存时，沿现有 TK 正源写入并读回。

## 3. 先展示什么

先直接回答当前问题，再列关键依据和适用条件。涉及本场时，优先区分已核实事实、历史材料、系统推导和待核实项；涉及价格时同时显示时间和来源。

查回已有认识时，首屏给出该认识的结论、来源和适用边界，原文与更多细节按需展开。当前赛事覆盖不足时，明确显示哪些只能依据历史材料，哪些不能确认。

不把其他品种的赛事页、盘口或结果当作无畏契约入口，也不让默认回答扩展到与问题无关的模块。

## 4. 怎样判断

历史材料可帮助理解某类地图、阵容或市场现象，但必须核对当前版本、队伍、选手状态和对手是否改变。可追溯的原文或明确用户判断优先于模型推测；两者冲突时保留来源、时间和差异。

价格与市场讨论必须区分历史赔率、当时可核实报价和当前未知状态。不能把旧价格当实时价格，也不能只凭一个历史结论声称本场一定适用。

项目当前能力为部分可用；没有当前赛事和价格来源时，系统应说明限制并继续回答有材料支持的部分，不补造事实。

## 5. 资料和能力边界

- 已有专项讨论方法、部分普通 TK 与交易 TK，并可查回原文和适用条件。
- 当前赛事与实时价格来源尚未补齐，跨游戏单场到复盘的完整链路未验收。
- TK 与历史材料不自动升级为当前事实或交易决定；普通讨论不暗中写入长期知识。
- 来源缺失、过时或冲突时显示具体影响；不编造比赛、阵容、地图、赔率、结果或已读取状态。
- 不自动下单，不用其他品种能力冒充无畏契约能力。

## 6. 怎样验收

| 场景 | 用户应看到的结果 |
|---|---|
| 查回一条认识 | 给出结论、来源、时间和适用条件，可回到原文核对 |
| 判断本场适用性 | 说明当前版本、队伍、地图或阵容是否已核实，以及缺口如何影响判断 |
| 讨论价格 | 标明时间和来源；旧赔率明确标成历史，不冒充实时价格 |
| 当前赛事资料不足 | 如实显示部分可用或未知，不以历史页面补齐 |
| 查看入口 | 只展示无畏契约已有入口和材料，不用 LOL 单场页代替 |
| 普通讨论 | 不发生 TK、画像、交易结论或状态的自动写入 |
