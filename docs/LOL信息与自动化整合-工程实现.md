## 3. 目标结构

```text
范围（唯一）          现在看哪些赛事/联赛
   ↓
事实（唯一）          赛程、结果、队伍、首发、价格    每条带来源 + 取得时间
   ↓
覆盖面（可计算）      每场双方在"谁上场 / 价格 / 结果"上的洞，可被脚本算出并读回
   ↓
触发（唯一排程器）    执行时刻由赛程算出：赛前出简报、赛后刷结果、无比赛不排
   ↓
出口（三条）          谁上场变了 / 价格到了 / 结果出了    其余留库，日报退成归档
```

四层之间只通过正源和合同连接，不互相复制：范围不复制队伍名单，触发不复制赛程，出口不复制事实。

## 4. 数据与正源设计

### 4.1 范围（唯一）

- 继续以 `current_event/config.json` 作为范围内的唯一声明（赛事名 + 联赛列表），不新增第二份配置。
- 新增**派生读取**（不落第二份正源）：由范围算出
  1. 范围赛事下的比赛清单（`schedules` 按 `leagues` 过滤）；
  2. 范围里出现的队伍集合（含待定名额产生的 TBD，TBD 不参与队伍缺口计算）；
  3. 范围区间（首发比赛日 → 最后比赛日）。
- 约束：派生只读，派生结果带 `as_of` 与派生规则版本；范围变更后无需人改任何名单。

### 4.2 事实（唯一）

| 事实 | 正源 | 必须带 | 备注 |
|---|---|---|---|
| 赛程 | `schedules` | 来源（如 `scoregg:*`）、更新时间 | 支持改期与 TBD 名额 |
| 结果 | `matches` | 库内写入时间 | 状态 completed/not_found 可判 |
| 队伍 / 首发 | `teams`、`rosters` | 更新时间、在职状态 | 首发变更 = 出口信号之一 |
| 画像 | `team_profiles` | `updated_at` | 陈旧需显式标注 |
| 价格 | 尚无 | — | 立项第 4 步接入；在接入前一律返回"无价格来源"，不得用历史赔率顶替 |
| 库外队伍事实 | `gol_gg` | `source_url`、`retrieved_at` | 第 3 步改为可留存（新增落库写入），仍不覆盖正式赛果 |

外部事实入库统一走一条入口（`business_mutations` 的 `team_intake` / `lol_price`）：只在缺失处写入、不覆盖已有事实、必须带来源（`source.kind` / `source.ref` / 时间），落库后来源与"是否人工核实"在读取侧可见。

规则：每条事实的取得时间必须能被前端/模型直接看到；同一事实多来源冲突时并列，不覆盖、不折中。

### 4.3 覆盖面（可计算）

新增只读计算：给定范围与日期，输出每场比赛的三项覆盖状态与洞清单。

- 三项：`lineup`（谁上场）、`price`（价格）、`result`（结果）。
- 每项状态：`ok` / `stale`（带陈旧天数）/ `missing`（无来源）/ `pending`（未到期，如未开打）。
- 洞清单同时进入能力结果合同的 `gaps`，不另建第二套缺口表。
- 这是 PRD"没有洞"验收口径的唯一计算入口，前端、模型和大文档出口共用同一结果。

## 5. 自动化触发设计（本项目核心）

### 5.1 唯一排程器

新增唯一排程器脚本（拟 `~/.hermes/scripts/lol_auto_planner.py`，no-agent 模式执行），职责只有一件：**把赛程翻译成受管任务的执行时刻**。

- 输入：范围（4.1）+ 赛程（4.2）+ 受管任务表（5.2）。
- 输出：每个受管任务的下一次执行时刻，写入前先 `hermes cron edit <id> --repeat 0` 清掉一次性消耗上限、再 `hermes cron edit <id> --schedule "<ISO 时刻>"` 改期，最后按需 `resume`（顺序固定，原因见 5.4）；任务缺失时按受管任务表重建。同一次运行写一份排程回执（任务、时刻、依据的比赛、依据的赛程来源与更新时间），供读回。
- 触发时机：① 每天固定两次做保底重排；② 数据刷新完成后立即重排（赛程/结果一有变化就跟着走）。
- 无比赛：受管任务一律排到下一场相关时刻，不产生空转执行；范围区间结束后不排任务，并产生一条"本阶段结束"回执。
- 改期：赛程时间变了 → 重排后执行时刻随之改变。**没有人需要改钟点**，这就是 PRD 的验收口径。
- 幂等：同一赛程重复运行得到同一排程；时刻已一致且任务已无消耗上限时不写。

### 5.2 受管任务

| 受管任务 | 触发规则（由赛程算出） | 输出 |
|---|---|---|
| 赛后事实刷新 | 每场比赛结束预估时刻（按赛制时长上限）+ 一次兜底复查 | 结果入库；失败即告警 |
| 赛前简报 | 开打前 60–90 分钟（只有存在当日比赛时才排） | 一条短消息（今天看什么、缺什么） |
| 结果推送 | 结果入库且状态从 not_found 变 completed | 一条短消息（结果 + 与赛前判断的差异口径） |
| 失败告警 | 任一受管任务失败 / 超时 | 一条短消息给钧钧，不静默 |
| 变化推送 | 每小时比对一次：谁上场变了 / 价格到了 | 一条短消息（无变化则完全静默） |
| 日报 | 保留现有 07:00（钧钧 2026-10-17 决定保留，不退役） | 归档文档 |

不在本次范围：自动交易、自动改 TK、后台实时盯盘、为每个对象建独立任务。

### 5.3 失败可见

任何受管任务失败必须产生一条用户可见消息（stderr/stdout 非空即视为失败），并把失败写进排程回执。禁止"任务失败但用户只能靠重复提问发现"。

### 5.4 受管任务的形态约束（2026-10-17 实测补记）

受管任务不是"每场新建一个任务"，而是**同一个 Hermes 一次性任务（once job）被反复改期复用**。Hermes 的 once job 创建时自带 `repeat.times=1`（消耗上限一次）：跑过一次后 `completed=1`，若只改时刻不改消耗上限，到期扫描会命中 `one-shot dispatch limit reached — removing stale due entry` **把任务直接删除，脚本再不会执行**。2026-10-17 11:30「LOL赛后刷新」就是这样消失的（当天赛果未刷新、结果未推送、次日赛程仍是 TBD），同一次缺陷还让失败告警把"任务停用"误判成故障。

- 因此武装顺序固定：`--repeat 0`（`repeat.times=null`，即不设消耗上限）→ `--schedule` → 按需 `resume`；顺序不能反。受管任务的定义（名字/脚本/投递目标/workdir）收敛在 `config/system_config.json` 的 `automation.managed_tasks`，任务被删时由排程器重建。
- 失败告警的判据以排程回执为意图正源：只报"回执排了时刻却没武装/到点没跑/被暂停"和"回执过期"；跑完停在 `completed`、或本阶段无比赛被暂停，都是正常作息，不告警。
- 回归测试：`tests/test_lol_auto_planner.py`（含用 Hermes 自身 `cron.jobs.get_due_jobs()` 做的到期扫描对照）、`tests/test_lol_automation_watchdog.py`。

## 6. 出口设计

- 三条推送共用同一消息模板：一句结论 + 依据来源与时间 + 一个需要钧钧决定或注意的点；不带内部字段、路径、表名。
- 其余内容不进推送：进库、进工作台、进按需读取。
- 日报退成归档后，工作台与归档文档只做保留，不再驱动用户每天阅读。
- 推送失败按 5.3 告警；同一条信号 24 小时内不重复推送。

## 8. 施工顺序

按 PRD 四步；每步独立验收、独立回退，前一步不依赖后一步成立。

### S1｜收拢事实 + 接上范围（只读）

- 实现 4.1 范围派生与 4.3 覆盖面计算，暴露后端只读能力，并在真实数据上核对。
- 不动 cron、不动写入、不落第二份正源。
- 验收：范围视图能给出区间与队伍集合；覆盖面能对真实比赛给出三项状态与洞清单，且与真实库一致；TBD 名额不误报为缺口。
- 回退：只读能力可整体下线路由，无数据副作用。

### S2｜任务跟着赛程走

- 实现 5.1 排程器与 5.2 受管任务，先把"赛后事实刷新"和"赛前简报"接入；保留原有 05:30 数据就绪作为过渡兜底，验证期后停用。
- 验收：改一条真实赛程时间 → 排程回执里的执行时刻随之改变，且无人改钟点；连续三天无比赛 → 不产生空转执行；任一受管任务失败 → 用户收到告警。
- 回退：受管任务退化为原固定钟点，排程器可停用，不影响入库正源。

### S3｜补库外队伍（gol.gg 落库）

- 在 `gol_gg` 现有只读能力上增加可留存的落库写入（新增本地留存表，不覆盖正式赛果/画像/版本正源），保留 `source_url` 与 `retrieved_at`。
- 验收：范围里库外队伍能被查到并留存；重复抓取幂等；正式正源未被覆盖；取不到时返回明确缺口。

### S4｜接价格

- 先确定稳定来源并登记来源合同（来源、频率、时间口径、未结算处理），再接入；来源未确定前只保留缺口。
- 验收：价格带来源与时间；无来源时返回"无价格来源"，不返回历史估值；不把未结算快照当实时报价。

### S5｜换出口

- 接三条推送与失败告警；日报退成归档。
- 验收：真实比赛日收到的是短消息；人为失败一次能收到告警；同信号不重复推送；归档路径仍可查。
