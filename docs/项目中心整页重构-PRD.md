# 小雪项目中心整页重构 PRD（待确认）

> 本 PRD 只处理“项目中心页面和内容怎么重构”。比赛资料怎么收集，另见《当前赛事信息收集能力重构 PRD》。两项不合并施工。
>
> 审计基线：2026-10-19。项目中心的设计事实来自现有项目中心内容、开发模块树、系统结构图、对象目录和待修改/交付闭环。

## 1. 这项任务解决什么

项目中心现在不能完整代表小雪项目：页面、后端能力、实际入口和开发模块登记之间对不上，用户看得到功能，却不知道每项能力解决什么、目前能做到哪、缺什么、应该从哪里继续。

这项任务不是新增一个“当前赛事收集能力”页面，也不是把项目中心改成比赛资料报告页。它只把项目中心重新写成一张可靠的项目地图，并把各项能力登记清楚。

## 2. 项目中心的设计理念

项目中心是给钧钧看的“项目用户视图”，回答：

- 小雪这个项目整体要解决什么问题；
- 现有能力分别放在哪里；
- 每项能力现在实际能做什么；
- 资料从哪里来、会给谁使用；
- 当前缺什么、从哪里继续；
- 一个问题如何进入待修改，改完如何回到真实入口体验。

它不是：

- 某一场比赛的详细资料报告页；
- 后台任务、报错和健康状态的总面板；
- 给用户看的技术实现目录；
- 按每个新问题不断增加新分类的功能清单。

项目中心只登记能力和项目关系。比赛的详细信息底稿仍由当前赛事/单场使用链提供；本次收集能力的具体改造见另一份 PRD。

## 3. 固定结构，不新增分类

项目中心现有页面分类保持不变：

1. 项目开发书
2. 系统结构图
3. 交易对象目录
4. 开发模块
5. 待修改与处理
6. 当前交付
7. 使用说明书

“开发模块”里的一级用户模块也保持不变：

- 资料与长期理解
- 当前赛事与单场准备
- 方法与判断
- 临场记录与交易后回溯
- 知识与数据底座
- 日报与自动化
- 工作台体验与项目能力
- 小雪对话能力与固定边界

比赛资料收集、内部/外部信息、版本、方法、首发和阵容，不得另立项目中心分类，只能挂到已有模块或已有二级能力下。

## 4. 页面内容怎么重写

### 4.1 项目开发书

说明项目目标、统一主线、角色边界和当前大方向。它讲“这个项目怎样工作”，不列具体比赛资料，也不把每个技术模块展开成说明书。

### 4.2 系统结构图

保留现有统一主线：人、小雪、信息、普通 TK、交易 TK、当前判断、结果与复盘。它说明内容如何流动，不新增“当前赛事收集”节点作为项目中心栏目。

### 4.3 交易对象目录

继续登记赛事、比赛、队伍、选手、版本、TK、盘口和结果等对象的覆盖、来源和缺口。它回答“项目正在处理哪些对象”，不承载某场比赛的完整资料底稿。

### 4.4 开发模块（本次重点）

开发模块登记能力，不登记文件名。每个一级模块和二级能力都要用用户能看懂的话说明：

| 需要说明的内容 | 具体要求 |
|---|---|
| 解决什么问题 | 先写用户能得到什么，不先写技术名 |
| 什么时候使用 | 入口、触发语境和适用范围 |
| 处理什么信息 | 赛程、队伍、版本、首发、BP、TK、赛果等 |
| 信息从哪里来 | 内部正源、正式数据、外部搜索或用户输入 |
| 收到后给谁用 | 当前赛事、单场、对话、记录、复盘等 |
| 当前实际能力 | 已能做什么，不能把“有接口”写成“已可用” |
| 内容缺口 | 缺什么、过期什么、哪些还没核验 |
| 边界 | 不会自动做什么，哪些需要用户确认 |
| 从哪里继续 | 一个真实入口或下一步动作 |

本次要把“当前赛事与单场准备”及相关“知识与数据底座”“方法与判断”能力中的信息收集说明补齐，包括：

- 点名比赛后应该主动收集哪些资料；
- 内部资料和外部搜索分别承担什么；
- 版本、方法、首发、阵容信息是否有可靠依据；
- 收集结果供当前赛事、单场判断和复盘怎样使用；
- 内容不足时如何显示缺口。

这些是开发模块里的能力说明或二级能力，不是项目中心新分类。

### 4.5 待修改与处理

保留原有闭环：从任意模块记录“不顺” → 回到对话把问题说清楚 → 进入正式处理 → 改完进入当前交付。待修改不等于已经承诺施工。

### 4.6 当前交付

只展示用户可以实际体验的交付结果、验证证据和反馈入口，不用技术状态代替体验结果。

### 4.7 使用说明书

说明“我想做什么时应该从哪里开始、可以怎么跟小雪说、会得到什么”。它与开发模块使用同一份能力事实，不再手工维护第二套模块清单。

## 5. 内容同步要求

项目中心的模块说明必须有唯一内容来源：

- 修改模块能力时，只改唯一的项目中心内容源；
- 项目中心页面、使用说明和小雪的能力菜单从同一份内容读取或生成；
- 不允许页面写一份、说明书写一份、对话菜单再写一份；
- 每次内容更新后自动校验模块 ID、入口、能力映射和缺口字段，避免项目中心与真实能力再次脱节。

这项同步只解决“登记内容一致”，不等于比赛资料已经自动收集；比赛资料收集由另一份 PRD 验收。

## 6. 本任务不做什么

- 不新增“当前赛事收集能力”分类；
- 不改当前赛事页面的布局、卡片和交互；
- 不在项目中心展示某场比赛的详细资料底稿；
- 不把项目中心做成后台健康、报错或自动化运行面板；
- 不在本任务内实现外部联网搜索、赛程排程或主动推送；
- 不改交易判断、不自动交易、不迁移真实业务数据。

## 7. 验收标准

1. 项目中心仍只有原有页面分类和原有一级开发模块，没有新增业务分类。
2. 从项目开发书能看懂小雪项目主线，从系统结构图能看懂信息如何流动，从对象目录能看懂对象覆盖，从开发模块能看懂每项能力现在能做到哪。
3. “当前赛事与单场准备”及相关模块能说明比赛资料收集的内部/外部分工、信息范围、缺口和真实入口。
4. 页面、使用说明和小雪菜单对同一模块使用同一份内容事实，更新一处后能同步核对。
5. 待修改、正式处理、当前交付的闭环仍然可用，且每条记录能回到具体模块和用户问题。
6. 进入项目中心时，用户看到的是能力地图和可继续动作，不是技术名词墙或状态报表。

## 8. 施工前确认

确认本 PRD 后，才开始项目中心页面和内容改造。当前赛事信息收集是否能主动查齐，单独按《当前赛事信息收集能力重构 PRD》确认和验收。
