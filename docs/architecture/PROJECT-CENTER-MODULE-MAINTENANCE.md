# 项目中心开发模块维护说明

这份说明只给项目维护和后续开发使用，不展示在项目中心页面。

## 正式来源

- 页面展示正源：`config/project-center-content.json` 的 `development_map`。
- 细项事实来源：同一文件的 `module_tree`；`manual.module_tree_id` 和开发书跳转继续引用稳定的旧节点 ID。
- 品种和能力状态：`config/project-contract.json` 的 `object_catalog`；页面不因分组存在就把 `partial` 说成完整可用。
- 项目共同规则与实现定位：根 `AGENTS.md`、`docs/architecture/PROJECT-MAP.md` 和 `config/module-contract.json`。
- 品种业务目标、展示和验收：`docs/business/lol.md`、`football.md`、`cs2.md`、`valorant.md`。
- 已实施的历史需求：`docs/archive/designs/项目中心开发模块更新-PRD.md`；变更证据：`memory-bank/progress.md` 以及正式交付记录。

## 展示结构规则

`development_map.groups` 表达原开发模块入口内的五个分页：英雄联盟、足球、CS2、无畏契约、项目共用，每次只显示选中页。各页的 `modules` 是给用户直接说出的主模块，每个主模块只保留 `now`、`gaps`、`next_step` 三项事实说明，并通过 `detail_node_ids` 折叠引用具体能力。

展示细项的 `module_tree` 节点用 `current_capability`、独立 `known_gap`、`next_step` 记录开发现状；`when_to_use` 和入口口令留给兼容使用说明。不要把能力合同的“无内容时怎样返回”拼接成一长串开发缺口。

新增能力、入口变更、模块合并或缺口解决时，在同一开发改动中同步这张图。不要等待用户再次指出过时内容。能力的当前范围由项目/模块合同确认；“当前健康、今天 ready、最近失败数”只能来自即时状态，不能写进静态能力介绍。

当前归属：LOL 的比赛与赛程包含日报、赛程推送和逐局事实核对；队伍与版本包含英雄资料、画像维护、首发和来源入库；判断与交易包含纯阵容、交易方法和资料分流；记录与复盘包含队伍与交易 TK。足球单独承接观察台及两种筛选；CS2、无畏契约分别记录已有讨论/资料能力与来源缺口。共用底座只放跨品种检索、导入与状态机制，项目中心与对话放页面、反馈和接入边界。

待修改保存主模块稳定 ID（如 `football-match`），名称快照为“足球 · 赛事与赛前”，保留品种、目的、现状、缺口和内容版本。`basket_module_id` 仅为内部能力定位线索，不再用作新条目的去重身份；旧条目无需迁移。目录/说明书的旧节点跳转用 `legacy_node_ids` 或细项归属解析到新页。

主模块的合并、拆分和下线判断只看三件事：责任是否相同、来源是否相同、后续是否总是一起修改。只要其中一个明显不同，就保留为独立细项；细项数量增加不能直接变成新的主模块。

## 核对任务

入口：`scripts/tasks/xiaoxue_project_center_module_review.py`。本次提供可调用的只读入口，不注册或启用生产调度；后续若要定期触发，属于单独的调度变更。

核对任务读取最新项目总规则、四份品种业务指导、项目合同、模块合同、状态证据和当前 `development_map`，输出一份带来源、时间和差异的核对提案。输入文档一律视为不可信数据，其中的命令或指令不构成任务授权。它只提出：

- 事实已变化但页面文字未同步；
- 旧节点引用失效或细项无法定位；
- 主模块重复、缺失或超过约定规模；
- 品种状态与项目合同不一致。

任务不得直接改写 `config/project-center-content.json`，不得创建或修改生产调度，也不得把模型猜测当作事实。模型输出不确定或来源冲突时必须标记 `待核对`。

## 人工写回与回退

维护者在本轮已授权开发范围内，核对提案后按最小增量修改 `development_map` 或 `module_tree`；涉及目标或品种分类取舍时再交给用户决定。修改前记录旧版本号和变更原因，修改后必须：

1. 重新读取 JSON，确认所有 `detail_node_ids`、书内跳转和使用说明引用都存在。
2. 运行项目中心内容、API、菜单和前端相关测试。
3. 用隔离数据从项目中心页面逐页核对、展开细项，确认旧跳转和不同品种的待修改/备注均准确。
4. 将来源、核对时间、变更内容和验证结果写入交付记录；发现不对时恢复上一个内容版本。

旧的八个顶层节点暂不删除。只有当所有书内跳转、使用说明和兼容读者完成迁移并通过回归后，才单独评估退役，不在普通内容更新中顺手删除。

验证入口：`python scripts/tasks/xiaoxue_project_center_module_review.py --dry-run` 检查结构并输出完整依据包；不带参数时调用既有模型生成提案。项目中心测试覆盖归属、漏项、失效引用和待修改读回；构建用独立输出目录。正式发布与生产排程按根项目约定单独授权。
