| 版本理解/画像/TK | 原正式记录ID、修订或正文hash、认可状态、有效版本/人员/时期；旧记录缺状态不得补造“已认可” |
| 原文/字幕 | 规范URL/文档ID、作者、发表时间与精度、事实发生时间、取得时间、正文hash、正文读取状态；取得时间不替代发表时间 |

现有match仓储扩展明确的`event/team/match`对象范围；赛事/队伍准备不编造双方或虚拟赛程以挤入match。缓存只存可追溯内容与引用，不承担第二份正式画像。新增范围通过同一仓储与public暴露；既有match键和读接口兼容，旧快照不改写。

同场身份继续使用规范赛事/双方/时间/赛制及已知正式ID；同队重赛、改期、待定对阵分别处理。依赖包含版本/名单/画像/TK/方法hash，变化只使关联的当前成果待更新，其他结果复用。采集时间单独变化不生成假修订；语义或状态改变必须进入修订身份。

后台对PRD第3.2节逐项记录对象、实际可读内容、有效时期、负责模块、状态、恢复动作。只有“有有效内容”“确未公开/方法不适用”“仍待处理/故障”三类含义；后两者不伪装补齐。记录从实际内容和任务生成，用户不维护。正文只带影响使用的限制，不展示工程缺口墙。

回放按`as_of`只取当时已可得输入和版本；赛后新文、补录结果、后来确认的首发均不进入原赛前快照。锁、generation/attempt租约、原子替换和旧worker隔离保持；新schema/collector版本须兼容识别旧产物，不把旧翻译稿升级为完整分析。

## 4. 先补S16实际内容，再共享使用

1. 从正式赛事来源核对本届参赛对象、阶段、赛制、时区及实际比赛版本，与现有`current_event/config.json`及原范围/赛程链对齐。保留来源和差异，不硬编码本文举例或把库里出现过的四支队当全名单。未抽签TBD是正常状态，不算具体对阵已齐。
2. 对所有已确认参赛队检查当前名单、画像、近期比赛与已有认识。沿用当前队伍关注政策分配深度，但每队都要有真实、相关的可读基础，不用模板画像填满。旧MSI/国内赛认识核查人员、版本和打法后复用；不可比TS、旧INTL种子不用作当前跨区分差。
3. 正式版本理解读`version_understanding.public`，画像读`profiles.public.get_current_profile`，TK读`tk_knowledge.public`并取回正文。旧镜像不顶替正式记录。正式内容不适用时，可先给带系统身份的当前证据与推导；需要确认的长期修正待原能力处理，不阻塞阅读。
4. 保留已修原导入executor及当前Hermes runtime，不重复修不存在的旧Provider问题。B站取得字幕，公众号沿原发现与正文工具；验证页、搜索摘要、截断或元数据不入分析。公众号受限时换当前已有可用渠道找相同问题的实质分析，不保证取得受限文章，不绕登录/付费。
5. 外部检索针对当前赛事、队伍打法、版本、复盘和采访，也保留有实质理由的preview/prediction。来源清单及预算登记在当前赛事原配置，不新开来源管理后台。每个约定来源在同一截止点复核漏收/误筛；来源名单不能临交付缩小来制造覆盖率。
6. 粗筛必须读正文，保留作者结论、论据、条件与反证及连续原句。新闻事实只能作背景，不能填充作者分析数量；队伍通用分析关联本场时标明小雪推导。转载合并表达但保留出处链；相反观点及独立论据不合掉。
7. 公共准备管线复用`internal → library → external → digest → analysis → save`；先有有效内容即可读，失败不抹旧成果。赛事和队伍已有正文/hash在同场复用，单场只补差异与必要分析；每场不得重跑所有来源和方法。

URL只接受公开http(s)，拒绝凭据、私网和重定向绕过；不把私人判断发到搜索服务。不从文章猜首发、BP、价格或结果。正式知识/事实变更仍走原唯一写入器及授权，预备缓存不能悄悄升级为已认可知识。

## 5. 看得见的判断入口与个人内容衔接

### 5.1 一个目录，页面和对话共用

扩展原`config/trading-methods.json`，保留已有说明字段与兼容读。每项增加稳定`id`、排序、适用对象范围、内容类型、能力绑定、保存归属及接通状态；专业方法正文不复制进去。`get_trading_methods`与原`GET /api/trading-methods`返回同一目录，移除`len == 5`；按唯一ID、必要字段和实际handler核对，不按卡片数量验证。

能力绑定只允许命名好的内部handler，不允许配置任意文件路径、URL或可执行代码。新增已有能力的视角只需登记现有handler；新方法未开发时明确未接通，不显示假“立即使用”。原交易总纲保留为共用依据；原阵容与赛后卡保留原用途，不作为本次赛前必走项，也不为了凑五项直接替换掉。

前端复用原`event-methods-list`，取消默认隐藏整个目录和固定五列布局；每项仅简短说明能判断什么及进入按钮。目录不是默认阅读前置页，打开比赛仍先读成果。选择视角只请求相应上下文，不批量运行全部方法，不创建match_run或自动保存。

唯一产品MCP增加同源目录/上下文命名工具，内部均走上述API与public，不自维护第二份列表。飞书先用实际支持的文字选项：列出可读标题，用户回复序号或自然指代后读取对应上下文继续；序号只在当前目录版本和会话内解析，不要求长期记口令，不宣称已有聊天交互卡按钮。小雪根入口仅接已有赛前引导，不复制方法清单。

### 5.2 进入后直接看到什么

在`current_event`内增加只读上下文接点`GET /api/current-event/judgment-context`，参数为目录ID及赛事/队伍/比赛身份、可选`as_of`。返回匹配目录项、实际内容引用与正文、有效性/认可身份、相关准备结果及能力状态。缺少必要对象返回明确的待选对象，不编造队伍；版本视角不要求比赛，队伍视角只需队伍，确需比赛的视角才问比赛。

| 对应内容 | 读取与实际判断能力 | 明确保存时归属 |
|---|---|---|
| 版本理解 | 全局正式内容＋本届核查证据；复用原版本维护/简报规则 | 原版本维护能力与`shared_version_analysis`；当前只读API不冒充已有保存接口 |
| 队伍画像 | 当前队伍唯一画像＋名单/打法变化证据；复用画像能力 | 原team_profile写入器，禁止Wiki第二画像和独立三维维护 |
| 周期与实力 | 同口径指标＋近期事实，复用`lol-cycle`；跨区不硬比分数 | 临时解释留会话；明确记录走原单场，不改TS数值、不新建周期库 |
| 交易TK | 条目全文/状态/条件/反例＋本场关联，复用原交易方法 | 原TK条目维护；本场采用单独走原单场，不自动改长期认可 |
| 本场判断/预案 | 同场已准备内容＋实际引用和用户已有记录，复用原赛前引导与交易方法 | 原entries或trade-plan写入能力，按本场用途选择，不双写 |

页面在原当前赛事内展示可继续判断的内容区，带当前对象和返回比赛动作。现有文本框只是记录，不能假装AI对话已接通：本轮在同模块增加显式`POST /api/current-event/judgment-discussion`，由用户提问后才调用同一既有方法执行器，返回回答及引用，不执行采集全流程、不写正式内容或用户记录。临时对话仅会话内保留；如需长期保存，用户明确触发原保存动作。无匹配现成网页保存能力的长期修订由小雪原维护能力承接，不伪造网页按钮已能写。

默认自动分析、显式讨论共用输入组装与正式方法，不复制模型提示词链。执行器仍使用当前Hermes runtime和有界调用；周期缺关键输入不出方向、版本/首发未核对不冒充已成立适配、交易方法不自动确认采用/金额。纯阵容不被此入口自动调用。

目录、上下文与阅读均只读；讨论是模型动作但不业务写入。保存由独立命名动作及原确认语义执行并读回。用户一句想法不自动成为候选、已认可内容或已保存预案；完整保留不做个人判断的路径。

### 5.3 修改后怎样更新

每条分析保留实际引用的内容ID、版本/hash和身份。用户指向某条分析可查看它真正使用的版本、画像、周期、TK，进入对应原内容，而不是一律打开泛笔记框。

正式修订读回后，对比依赖指纹，将引用该内容的当前分析标待更新并重新计算受影响部分；无关对象不重算。未确认建议仅以临时假设参与显式讨论。用户旧判断不改写；需要时提示其依据已变。旧日报、历史快照和用户原话不动。

公开观点和方法结论有共同命题才作相合/分歧比较，不能把报道背景和条件规则硬比较，也不把单个作者说成大众共识。

## 6. 原阅读入口、状态与消费契约

保留原collection准备/查询/resume、materials列表、match-desk等路径；API不改成新“平台”。新增判断上下文及范围查询`GET`不联网、不建表、不创建单场、不保存判断。判断入口先读已存成果，显式提问才调用讨论；本轮保留原选场触发幂等collection准备与局部轮询，不改成另一套刷新流程，准备失败不能抹掉旧成果。第5节新增接点及MCP命名工具同步注册，表现层不跨模块读内部文件。

任务状态和内容状态分开。`delivery`保留粗筛状态、实质作者分析、方法推导scope及限制：筛选完成不等于取得作者分析；条件推导不等于本场事实已支持；局部ready不代表S16整体补齐。未公开/不适用有证据和理由；应可得但失败仍是待处理，禁止为过验收改名。
