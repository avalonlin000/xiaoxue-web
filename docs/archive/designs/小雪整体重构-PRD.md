# 小雪整体重构 PRD：赛前准备与快速收尾版

> 修订：2026-10-21。层级：项目。钧钧明确核心是小雪替他把比赛准备信息尽可能查全、整合好。保留自用、快用、砍边角工程；不得把信息补齐主线从项目范围里省略。
> 同一次重构，不另建项目。本次约定的快速收尾已发布：批次覆盖、逐场已有要点和网页／产品工具读取已核对，登记名单误标首发已修正；当前8场仍为部分整理，不冒称信息完整或可靠交易结论。最终范围、读回证据和限制见[SSD第12节](小雪整体重构-SSD.md#12-快速收尾交付2026-10-21)。

## 1. 最终要得到什么

小雪把关注窗口内的已确认比赛准备到可直接研究：找出要准备的比赛；复用赛事、双方和版本资料；发现重要信息缺失或过时；沿现有来源补查核实；去重后整合到对应比赛，呈现支持、反例、条件和未补原因。钧钧不必逐场催继续、搬材料或维护收集清单。

重点依次是：信息够新、材料拼得起来、内容服务当前问题、使用省事。长期沉淀和复盘够用即可。小雪可以分析、给不同意见，交易取舍由钧钧决定，不承诺自动发现盈利机会。

## 2. 改完怎样用

- **准备一批比赛：** 用户说“准备24号的比赛，先整理重点”。小雪从现有关注赛事和赛程找出已确认对阵，为每场复用赛事／双方／版本资料，补查仍影响本场的问题。逐场交准备结果，或说明未发布、来源无正文、核实失败、预算耗尽等缺口；不能漏场，不能把目录或空状态算完成。用户不必逐场调工具、搬来源或反复催继续。
- **研究一场：** 网页点进比赛，直接读本场新变化、双方情况、观点对照、支持和反例、条件及出处。赛事共用材料按适用范围复用；本场资料回到正确比赛，不串场。
- **检验想法：** 飞书说“我觉得这队近期的问题是……，找支持和反例”。小雪读取相关正文，对比材料和样本，说明可确认事实、推测及待核条件。网页就地讨论处理已有材料，补查新资料沿现有飞书能力。
- **留一点内容：** 明确保存后沿原记录／TK找回。不要求每场填预案、维护分类、改画像或做完整复盘。

网页和飞书按同一比赛身份、同一资料修订读取结果。网页用于浏览，飞书用于追问和补查；不能把已有读取工具说成整批准备、跨端聊天同步和持续补查都已验收。

## 3. 本次必须做好

| 重点 | 最低可用结果 |
|---|---|
| 近期比赛可进入 | 已确认对阵、时间、赛制正确，能找到近期场次；待定不编造，仍可先读赛事／队伍资料 |
| 新资料能用 | 沿已有来源补查相关变化，日期和适用范围可辨；旧背景、抓取时间不冒充新消息 |
| 缺口能收敛 | 逐场区分已核实、待复核、旧背景、未发布／取不到和等待有限恢复；先补会影响本场准备的缺项 |
| 材料真正整合 | 复用赛事、双方、版本、TK和原专业方法，围绕本场整理事实、对照和疑点，不只是链接和独立模块 |
| 结果真正交付 | 窗口内每场有可读结果，或明确说明缺什么、为何未取得、是否会有限自动恢复；重要正文、出处、条件进入对应比赛，不让用户自行拼材料或误以为后台仍在继续 |
| 失败能续接 | 预算／进程中断保留已取得材料与断点，沿现有限次恢复补缺；不能无限重试，也不依赖用户逐次发“继续” |
| 阅读讨论省事 | 正文和出处可展开；飞书按问题读必要内容，用户不用处理工具分页、搬运全文；同对象不无故重置、不串场 |
| 结果可核查 | 重要事实有对应来源，事实与推测分开；统计差异不直接证明原因，缺过程证据不编“输法” |
| 代码整理够用 | 保留已做共用逻辑和职责归位，只修主线实际遇到的重复和错误；不继续全仓拆分、改名、统一分类 |

资料不全、模型不完美不等于所有准备都不能用；任务不必全部显示完成。但不能把无依据的确定结论包装成可靠交易分析，也不能靠空态冒充有用底稿。

## 4. 可以省略或按需再做

| 事项 | 本次决定 |
|---|---|
| 完整冷／热基准、调用成本、节省比例 | 省略新增测量，已有证据保留，不回滚、清缓存或重跑研究凑数字 |
| 长期等待未来多日调度、日报和全部历史场次 | 不作前置；但当前关注窗口的批量结果与有限自动恢复属于必须交付能力 |
| 专门制造自然飞书入站、重复长程研究验收 | 省略；自然使用时核对未验部分，不能代用户发消息或伪造成功 |
| 长期TK／画像／版本修订全链新建设与真实写入演练 | 本次不新增，原能力保留，实际需要时沿原入口处理 |
| 大型复盘、评分、资料治理、统一全文索引 | 不做，原记录和找回够用，不增加用户作业 |
| 全部旧接口退役、兼容目录清零、统一全部文档分类 | 不做；有调用就保留，不因看起来旧而删功能或数据 |
| 反复全量回归、新门禁／评审模型 | 输入未变复用结果，只验证实际改动，不扩建收尾体系 |

这是钧钧本次授权的优先级调整，不是把未完成项改成已完成，也不是删除今后可按需使用的能力。

## 5. 必须保留的底线

不伪造对阵、人员、BP、盘口、比分、日期和出处；全年／旧阵容与当前样本分开。总体胜率、选边或队伍BP不能直接证明战术原因、选手职责和意图，推测在对应位置说明条件。

普通讨论不自动写交易、长期TK、画像或三维。沿原网页、数据库、业务正源和唯一产品MCP，不建平行系统。本次文档调整不扩大模型、SOUL、专业方法、权限、生产任务和外发授权。

不要求每句话做成论文式证明；影响本场判断的重要事实和解释必须能追溯。

## 6. 怎样结束这次重构

主线仍是：关注窗口的已确认比赛逐场发现缺口 → 复用／补查 → 有限续接 → 整合回各场 → 网页和现有产品工具可读。已有批次实现与原有限恢复继续使用；本次已核对8场均有可读要点及具体限制，不以单场标签修复代替批次能力。飞书自然对话中采用新能力的完整体验仍按未验披露。

自然飞书、未来连续供给、长期修订和完整性能比较可以明确列为未验／按需事项，不再拖住已验证范围的交付。对阵错误、关键依据丢失、内容不可读、串场或错误写入仍须修复。

收尾报告区分“本次约定范围已交付”与“研究／自动化全部通过”，不能混写。
