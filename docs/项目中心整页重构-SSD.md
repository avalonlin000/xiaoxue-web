# 小雪项目中心整页重构 SSD

> 对应 PRD：`docs/项目中心整页重构-PRD.md`
> 版本：2026-10-19.1
> 状态：已确认，进入实现与验收

## 1. 目标与边界

项目中心是小雪的项目用户视图。它只登记项目能力、能力与入口的关系、当前真实状态、缺口和继续动作；不承载某场比赛底稿，不替代当前赛事页面，不提供后台健康面板，也不自动写入 TK、画像、盘口或交易结论。

本次固定七个页面视图，顺序不可变：

1. 项目开发书
2. 系统结构图
3. 交易对象目录
4. 开发模块
5. 待修改与处理
6. 当前交付
7. 使用说明书

开发模块固定八个一级用户模块：资料与长期理解、当前赛事与单场准备、方法与判断、临场记录与交易后回溯、知识与数据底座、日报与自动化、工作台体验与项目能力、小雪对话能力与固定边界。

## 2. 正源与分层

### 2.1 内容正源

`config/project-center-content.json` 是项目中心静态内容唯一正源，包含项目开发书、八个一级模块及其二级能力、使用说明场景、对象目录和系统结构说明。页面、`scripts/xiaoxue_menu.py`、`docs/小雪项目总使用说明.md` 和小雪菜单都从这份内容读取，不复制模块清单。

每个模块节点必须具备：`id`、`name`、`purpose`、`when_to_use`、`current_capability`、`entry`、`ability_ids`、`boundaries`、`next_step`、`children`。二级能力沿用同一字段语义；缺口必须写在当前能力或边界中，不能用接口存在替代可用。

### 2.2 动态状态源

`/api/project-center/overview` 只提供项目摘要、运行状态、日报状态、对象目录和内容版本；`/api/project-center/modules` 将内容节点与当前模块状态合并，返回用户可读的状态、影响和缺口。业务模块只读，不由项目中心改写。

`data/project_center.sqlite3` 只保存项目中心自己的待修改篮子、正式处理请求和当前交付。写入必须有清理、幂等键、版本号和读回；项目中心写入失败不得影响业务数据。

### 2.3 适配层

后端通过 `xiaoxue_api.modules.project_center` 暴露项目中心 API；前端通过 `src/modules/project-center` 独立挂载。业务模块之间不直接互相导入，项目中心只通过公开 API 和应用事件导航。

## 3. 用户主路径

进入项目中心后先看到项目开发书的主线、边界和可继续动作；用户可直接切到任一固定页签，不需要按顺序浏览。

在开发模块中展开一级或二级能力时，阅读顺序固定为：解决什么问题、什么时候使用、处理什么信息、信息来源、收到后给谁用、当前实际能力、内容缺口、边界、下一步。工程字段只留给后端/调试，不进入用户默认视图。

“不顺”通过模块上的“加入待修改”进入待修改篮子。篮子只记录问题上下文，不承诺已施工；确认问题后才形成正式处理请求；交付记录必须包含用户可见变化、真实入口、验证证据和风险。交付反馈可以回到待修改篮子。

使用说明书与模块内容同源，按“我想做什么 → 从哪里开始 → 可以怎样说 → 会得到什么 → 何时不要这样用”组织，并提供复制给小雪的自然语言入口。

## 4. 前端契约

- 项目中心使用 `#project-center` 独立区域；切入项目中心时隐藏普通工作区内容，返回其他页签时恢复。
- 页面路由使用 `#project-center/{view}`，支持刷新和浏览器前进/后退；无效视图回退到项目开发书。
- 七个页签保持可见且顺序固定；窄屏使用横向滚动，不用全屏遮罩挡住主操作区。
- 待修改篮子为局部抽屉/窄屏内嵌区域；关闭后恢复触发按钮焦点，`Escape` 可关闭。
- 失败、空态和资料不足必须在项目中心可见；不以旧赛事、旧对象或技术状态静默填充。
- 前台不展示 `/api/`、数据库表名、内部 Skill、`mu/sigma`、YAML 或实现路径等工程词。

## 5. API 契约

只允许以下项目中心接口作为页面入口：

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/project-center/overview` | 项目开发书摘要、运行状态、对象目录、内容版本 |
| GET | `/api/project-center/modules` | 八个一级模块和二级能力的内容与运行状态 |
| GET | `/api/project-center/manual` | 使用说明场景和复制入口 |
| GET/POST/PATCH | `/api/project-center/change-basket` | 待修改篮子读取、创建、更新 |
| GET/POST/PATCH | `/api/project-center/requests` | 正式处理请求读取、创建、更新 |
| GET/POST/PATCH | `/api/project-center/deliveries` | 当前交付读取、创建、反馈 |

所有写接口必须保持幂等、版本校验和读回；禁止写入比赛、TK、交易记录、画像和项目模块合同。

## 6. 验证与回退

最小验证集：

- `npm run build`
- `python3 -m py_compile main.py xiaoxue_api/modules/project_center/*.py`
- 项目中心内容合同与模块覆盖测试
- 真实 GET `/api/project-center/overview`、`/modules`、`/manual`
- 真实页面从工作台进入项目中心，切换七个页签，展开模块，加入待修改并读回
- 窄屏页面检查页签可见、篮子不遮住主操作区、返回焦点正常

若动态 API 不可用，页面仍显示明确不可用状态，不伪造模块能力。回退只需恢复本次变更的前端/后端文件和内容正源；不触碰真实业务数据库，不执行迁移或批量写入。
