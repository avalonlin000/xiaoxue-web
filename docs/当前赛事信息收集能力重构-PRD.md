## 1. 要做成什么

把已有小雪的赛前内容和能力，该补的补、该合的合、过时的退出当前使用。以 S16 世界赛实际落实：钧钧开赛前直接浏览已经准备好的相关内容，有空再形成自己的判断，没空就不做。

这是自用项目，以阅读和使用效率为先，不以栏目数量、方法数量、报告字数或资料入库量证明完成。

必须同时解决五件事：

- 内容缺：有工具、标题或空表，没有实际可读的有效内容。
- 内容旧：旧画像、旧版本、旧比赛认识被当成当前情况。
- 内容多而乱：重复原文、指标、画像和分析分别堆在不同入口，让用户自己拼。
- 名称和流程多：用户必须记住某个方法、分析视角或口令，系统才开始工作。
- 责任不清：没人对内容准备到可用负责，采集或系统出错又把工作交回用户。

纯十英雄阵容分析、实时 BP 采集和逐局阵容推演不在本次范围，不成为赛前准备的依赖。人员名单与换人消息仍属于赛前资料。自动报价不作为本次新建能力；已有可靠价格可以使用，没有价格不能声称存在交易价值。

## 2. 用户怎样使用

### 2.1 不学名称，不调度方法

钧钧可以说“看看 S16”“这场赛前内容给我看看”，或直接从现有当前赛事页面打开比赛。不要求先选择视角、运行方法、收集底稿，再进入另一个流程。

这些说法只是例子，不是新增口令。小雪结合上下文识别赛事或比赛；只有对象确实不明且会影响结果时才问一个自然问题。

默认取用已准备的内容，后台按实际需要补充。用户主动点名某个已有方法、队伍或资料时仍可单独使用，不取消原有有效能力。

不要求记名称，不等于把可用视角藏起来。钧钧想主动判断时，应有第2.5节的可见统一入口，可以看到有哪些事情能做并直接进入；不必先说出某个方法的完整名称。

### 2.2 阅读优先，不强制走步骤

- 第一眼就能读到与当前问题最相关的具体信息和分析，不先展示目录、缺口墙或方法介绍。
- 相同事实只讲一次；共同背景只有影响本场时才带入，不整篇重印版本理解和画像。
- 关键理由、适用条件和重要分歧留在正文；原文、完整数据和推导依据按需展开。
- 不为短而删掉影响理解的反证，也不为完整而凑栏目、条数和字数。
- 再次查看能识别上次所读版本，突出重要变化；未建立阅读位置时不伪称“你已经看过”。
- 内容只有在实际改变认识或影响赛前使用时才主动提醒；无变化不重复打扰。

### 2.3 不把个人判断变成必填作业

外部作者的分析、小雪按已有方法做出的本场推导、钧钧自己的判断必须分清身份，但不要求用户先学三种新名称。

系统应主动准备前两类。钧钧有空可以讨论、纠正或记录自己的判断；没有时间、不回复、不记录，都不影响资料准备、分析更新和正常阅读。

系统不冒充钧钧已经认可、采用某条规律或确认某份预案，不代填交易动作、金额和仓位。

### 2.4 个人判断对应已有内容，不另建模块

个人判断不只是一条单场感想，也不是另加一份报告。钧钧可以对下列已有内容形成、检查或修正自己的认识；不要求每场逐项重做。

| 对应的已有内容 | 钧钧可以判断什么 | 讨论与修改的归属 |
|---|---|---|
| 版本理解 | 本届比赛版本主要怎么打，哪些旧认识仍成立，哪些要修正 | 查看当前正式版本理解及有关证据；明确更新时沿原版本维护能力处理 |
| 队伍画像 | 这队现在是什么队、怎么赢怎么输，人员或打法变化是否改变旧画像 | 查看对应队伍当前画像和变化依据；明确修改时回到该队唯一画像，不另存一份个人画像 |
| 周期与实力分析 | 如何理解双方当前状态、阶段和差距，哪些现象支持或反驳这种解释 | 查看当前指标及近期比赛依据，保留用户解释于原讨论或本场记录；不手改TS数值、不另建周期结论库 |
| 交易 TK | 已有规律是否认可、需要怎样修正，以及本场是否适用 | 回到原条目检查条件、反例和状态；本场采用与长期修订分开，不因一次讨论自动改条目 |
| 单场判断／预案 | 结合上述认识如何理解这场，哪些情况支持或推翻判断 | 沿原单场讨论和预案能力记录；只对本场成立的判断不反写长期认识 |

公开资料、作者观点和自动更新的数据是判断依据，不是要求钧钧逐项维护的作业。已有认识可以持续复用；某项没有用户认可内容时，如实区分小雪准备的分析，不摆空表催用户填写。

阅读本场分析时，必须能查到它实际使用了哪些版本理解、队伍画像、周期依据和TK，以及各自时点、用户认可状态或系统推导身份。未实际使用的内容不假装引用；有冲突或不适用时说明影响，不要求用户先解决才能阅读其他内容。

对话中钧钧指出某条认识，小雪直接带出对应内容与相关证据，接着讨论；页面提供从相关分析查看所用内容、进入原有讨论或修改入口的衔接，保留当前比赛位置。不要求用户先找到方法名称，不新增一个汇总所有个人判断的平行模块。

讨论、临时异议、明确修改和正式保存必须分清：只表达想法不自动覆盖正式内容；写入意思、对象与范围明确时沿原能力处理，遵守各自确认边界并读回。长期修改尚未确认时可继续讨论或作为明确标注的临时假设使用，不冒充已认可认识。

正式内容修改并读回后，重新检查引用它的当前赛前分析，只更新受影响部分，其他比赛不因无关修改重算。历史赛前快照、已冻结日报和用户原判断不被改写；若用户原判断所依赖的内容已变化，说明变化，不自动替用户修改结论。未做个人判断时，自动准备和阅读照常可用。

### 2.5 有一个看得见、能直接进入的判断入口

在原“当前赛事”页面复用现有方法展示位置，收拢为一个固定可见的入口，列出钧钧可以使用的不同理解视角。不新增一级页面，不放在项目中心，也不另建个人判断资料库。只浏览比赛内容的人可以不使用它。

- 每项用简短人话说明“可以帮我判断什么”，并提供直接进入的动作。版本、队伍、周期、已有交易规律和本场判断对应第2.4节已有内容；这些是当前起点，不是永久固定的五个入口或五步流程。
- 用户点击后，直接带入当前赛事、已选比赛或队伍，显示相关已有内容、准备好的依据和可继续讨论的位置。没有选比赛时，能先做赛事或队伍层面的判断；只有该视角确实需要具体对象时才询问，不要求先把所有步骤走完。
- 不能只有方法介绍、示例口令或一段让用户复制的提示词。选择某项就应真正接到对应内容与判断能力，不再要求用户重说“聊聊某某分析”。进入和浏览不自动运行全部视角，也不自动保存或修改用户判断。
- 小雪对话可展示同一份可选视角，用户可选择后继续；页面与对话不维护两份不同目录。具体对话选择方式由SSD按实际平台能力落实，不能把未实现的聊天按钮写成已有能力。
- 以后增加一个理解视角，优先关联已有能力、内容和保存位置，登记后就出现在同一入口，不需要用户记新口令或寻找新页面。有重叠先合并，不为每个新增角度另建系统。确需新方法或工程能力时按原边界开发，尚未接通的明确标注，不伪装成可直接使用。

执行时优先扩展现有方法配置与展示链（当前配置为`config/trading-methods.json`），复用原内容和执行能力，取消固定五张卡的数量约束。原卡片主要是说明；本轮必须实际接通内容和讨论，不能以说明卡代替统一入口，实际结果见SSD第8.2节。视角数量、排序和说明可以按需要调整，专业方法正文不复制到卡片里。

## 3. 先用现有内容，不从空系统开始

### 3.1 本次起点

现有知识库、版本理解、队伍画像、TS/周期、交易方法、导入器、单场采集、对话工具、日报和排程器均是复用基础，不重新建库或重做全站。

原 SSD 第9节记录：提炼故障、粗筛、方法推导、跨日准备和阅读消费已存在部分实现，但真实样本仍只有报道背景和条件推导，不能证明有效作者分析覆盖、当前输入齐备或连续赛前交付。旧能力地图还包含 Wiki 版本镜像、三维独立维护等与较新规则冲突的描述，不能照抄为施工事实。

施工前只复核下表涉及的实际入口、内容和运行状态。已有实现有效就保留，不因本次改名再次从头开发；未验证的能力如实记录，不能用旧测试数宣称本版通过。

### 3.2 现有内容的处理决定

下表是执行者的工作清单，不是新增用户菜单。S16 是当前应用范围，不是第二套知识库。

| 现有内容或能力 | 本次处理 | 完成后读到什么 | 主责开发模块 |
|---|---|---|---|
| 赛事范围、赛制、赛程、晋级与抽签 | 接入并补齐 | 当前真实阶段、北京时间、已确定对阵和正常待定项；不拿占位赛程冒充完整对局 | 当前赛事与单场准备 |
| 全局版本理解 | 保留并修冲突 | 核实 S16 实际比赛版本，检查旧认识、补当前证据；正式认识与尚待确认的修正分开 | 知识与数据 |
| 队伍画像、原三维和旧实体笔记 | 合并重复、补当前内容 | 每队使用唯一正式画像；原三维不再独立维护，旧笔记只作证据或历史 | 知识与数据 |
| 本届参赛队与选手资料、注册名单和首发 | 接入并补齐 | 覆盖当前参赛队；区分注册选手和本场已确认首发，不要求先为每人新建长画像 | 知识与数据 |

| 普通 TK、队伍 TK、交易 TK | 相关检索、合并重复表达 | 找回当前有效的知识、规律、反例及本场适用条件；保持资料和交易认识的不同身份 | 知识与数据 |
| B站、公众号和已有外部搜索 | 合并公共处理、修断链、补可用来源 | 实际正文或字幕经阅读和粗筛后的作者观点、理由与限制；搜索摘要不扩写成分析 | 知识与数据 |
| 多个分析视角、队伍版本简报和赛前引导 | 合并重复工作、保留独有方法 | 一次自然请求自动选择和组合；相关结果在一起看，不要求分别启动或逐步回复 | 当前赛事与单场准备 |
| 单场采集、资料展示、系统推导 | 接入同一成果 | 同场资料、公开分析和方法应用一致可读；已确认用户内容独立保留 | 当前赛事与单场准备 |
| 赛前简报、变化提醒和原日报 | 合并重复内容生成，保留原渠道 | 简报给成果而非报齐缺；日报提取当天相关内容，不另写一套结论 | 日报与自动化 |
| 个人讨论、判断、预案与原始记录 | 保留并接通第2.4节对应内容 | 读分析可找到所用认识，想判断或修正时回到原内容；用户可以不做，原记录不被自动覆盖 | 当前赛事与单场准备 |
| 赛后和阶段复盘 | 保留边界 | 保存当时赛前依据供原复盘使用；不强制启动维护或新增复盘项目 | 原模块，本次仅提供依据 |
| 纯十英雄阵容分析及实时BP | 本次退出施工范围 | 原能力不删、不改；缺BP不影响赛前内容准备 | 原模块，不纳入本次完成条件 |
| 项目中心 | 保留项目用途 | 只解释能力、修改申请和交付状态；不承载比赛正文、日报阅读或业务流程 | 原模块，不扩张 |

## 4. 合并要真的减少重复工作

不能只隐藏方法名，也不能把所有方法揉成一个没有专业约束的通用提示词。

| 重复处 | 必须实施的合并 | 不得丢失 |
|---|---|---|
| 各种分析分别查同一场资料 | 同一场共用一次已核实的资料准备；相同输入不反复搜索、提炼 | 来源、时间、有效性及专业输入要求 |
| 画像、三维、旧队伍简介重复描述 | 正式画像一处维护，其他地方引用或兼容投影 | 原历史和有依据的不同阶段认识 |
| 多来源转载或同一观点反复入选 | 合并阅读表达，保留原始来源关联 | 独立证据与重要分歧，不能把转载数当共识 |
| 队伍版本、战术视角、赛前引导重复取数和复述 | 合并公共步骤；互补视角按问题协同，输出按内容组织 | 独有推理、适用边界和真实分歧，不靠删方法凑精简 |
| 对话、页面、简报、日报各自写一套分析 | 共用已保存成果，各渠道仅调整阅读长度和展示 | 日报冻结、用户原话和历史时点 |
| 相同目的的入口、别名和旧流程 | 一个正式实现；必要旧说法转到同一实现，不保留平行执行链 | 用户主动点名的有效能力及安全兼容 |

SSD 必须列出每项具体合并涉及的原入口、共享实现、保留差异、旧入口处理和回归证据。仅改显示名、折叠旧内容或新增一个总入口，不算完成合并。

已存在的兼容层不因本次整理被直接删除；删除、迁移、正式知识改写和 Skill 变更按原授权边界实施。本 PRD 不直接修改专业方法。

## 5. S16 的内容怎样补齐并保持有效

### 5.1 先准备当前赛事整体内容，再随对阵使用

将当前 S16 正式参赛队、实际比赛版本和赛制对齐既有范围，建立各队当前资料与可用认识。不只准备数据库里已经出现对阵的少数队，也不因关注等级较低就长期保留空档；研究深度可以不同，基本可读内容不能无人负责。

已有国内赛、MSI或其他阶段材料必须检查人员、版本、打法及时间是否仍适用。可用的引用，不适用的退出当前展示，历史原文不删除。不直接把旧时期分数、统一 INTL 标签或数据库种子当作当前可比实力。

对阵明确后，自动关联双方材料、筛好的公开分析及适用方法，补充本场需要的信息。没有专门讨论该对阵的文章时，可以使用当前适用的队伍、版本和打法分析，但必须说明本场关联是小雪推导，不能冒充作者已预测本场。

### 5.2 “都有内容”怎样判断

执行方在既有 SSD/进度中维护后台核对记录，逐项对应第3.2节的适用内容：对象、实际正文或结果、来源、有效时期、更新时间、负责模块及未解决原因。用户不维护这份清单，也不用逐项催促。

每一项只允许如实区分：

- 已取得当前有效内容，并能从实际入口读回。
- 确实尚未公开或方法不适用，说明理由、影响和后续触发条件。
- 应当可得但未取得、过时、读取失败或尚未分析：仍是待办或故障，由系统继续处理，不算补齐。

空标题、“暂无”、相邻队伍模板、旧文改日期、新闻背景冒充作者分析、条件规则冒充本场有证据的结论，均不算完成。

不保证互联网上任何内容都能取得，也不保证每队每个角度都有可证结论。确实受限须合理换源和有限恢复；其他成果照常交付，但不能把仍影响目标的受限项隐藏后宣布全目标完成。

### 5.3 时效不等于刚采集

同时识别来源发表时间、事实发生时间、适用人员与版本、核查时间和本场分析截止点。时间未知如实标注；今天抓取的旧文章不能冒充今天的新认识。

名单、版本、赛程、抽签、赛后证据或作者更正发生变化时，判断影响哪些内容，只更新相关部分。同一队刚打一场，不自动推翻长期画像，也不能让明显失效的旧判断继续展示为当前结论。

正常未公开、已经过时、尚未采集、工具故障不能混写成一个“缺失”。只有确实影响当前阅读或判断的限制才进入正文，工程失败由小白处理。

## 6. 怎样做到随时想看都有准备

不以“用户打开页面”作为首次准备的必要开关，不把用户回复“继续”作为后台推进条件，也不统一规定每周维护或每逢大赛重新维护全库。

| 实际变化 | 系统负责的动作 |
|---|---|
| 已授权关注的赛事或参赛对象进入当前范围 | 整理并核查当前内容，补齐第3.2节的适用项；首轮准备期间如实呈现进度和已有有效内容 |
| 新对阵确定、抽签或赛程调整 | 自动关联已准备内容，处理同队重赛、改期、跨午夜与待定对象，不串场 |
| 来源、人员、版本或近期比赛产生重要变化 | 核查后更新相关内容和受影响分析，不整份重复生成或只改时间 |
| 用户打开或自然询问 | 先读取已存成果，追问直接沿用；必要补查不能抹掉当前可读内容 |
| 无新内容、用户没空或未回复 | 继续必要后台工作，不催填判断、不重复提醒 |

沿用原赛前约90分钟交付目标：提前已确定的比赛应在此时有可读成果，不是此时才开始。对阵更晚确定的，立即准备并记录实际可读时间，不伪装提前交付。赛前90分钟不是唯一阅读窗口，初次准备完成后即可随时查看。

SSD 开工前须依据实际运行耗时，落实并验证检查间隔、首次准备和变化更新的最长等待时间、重试上限、运行预算及暂停恢复。未写出并验证这些值，不得宣称“自动跟上时效”。不得使用用户尚未授权的生产任务或变更安全配置来达标。

## 7. 内容放在哪里，谁负责

### 7.1 沿用正源，不新建平行资料库

| 内容 | 正式落点与边界 |
|---|---|
| 赛程、结果、队伍与人员事实 | 原数据库和命名写入能力，事实核实后更新；不从普通分析文字猜赛果或首发 |
| 已认可版本理解、队伍画像、普通/交易 TK | 各自现有正源；原三维仅兼容投影，不复制第二份“当前认识” |
| 外部原文、字幕、作者观点 | 原来源留存及导入链，保留出处；外部观点不自动成为用户认可知识 |
| 小雪本场整理和方法推导 | 已有单场成果与修订，引用输入；不覆盖正式认识或用户预案 |
| 钧钧原话、判断和记录 | 原单场与记录正源，按明确保存意图写入并读回 |
| 对话、工作台、日报 | 读取同源成果；日报保存当时版本，后续更新不改写历史 |

整理当前证据和生成本场推导可自动进行。正式版本理解、TK、方法修改及其他写入继续遵守各自已有边界；已明确授权范围内的普通业务维护不新增逐次审批。需要确认的长期改动可以待定，不阻塞有明确系统身份的当前分析。

### 7.2 三个既有开发模块承接，不增加用户模块

| 主责模块 | 必须负责到底的结果 | 上下游关系 |
|---|---|---|
| 知识与数据（knowledge-and-data） | 内容取得、相关检索、去重合并、当前队伍与版本资料、来源与时效；不能只交原料和日志 | 复用既有画像、版本与知识能力，向单场供有效内容 |
| 当前赛事与单场准备（current-event-prep） | 本次端到端成果负责人：自然理解、自动组合方法、本场分析及完整阅读；识别缺项并协调补齐 | 消费前者，向所有阅读渠道提供同一成果 |
| 日报与自动化（daily-and-automation） | 不打开也提前准备，重要变化后更新，原渠道按时可读，失败有恢复 | 调用同一准备能力；不另做分析或另建日报 |

业务由小雪组织，工程由小白负责。钧钧负责目标、体验、自己的认知取舍和最终交易决定，不负责模块调度、搜索补洞、抄输入或查日志。

来源问题先由小雪补查；工具、任务或存储故障由小白接手。只有需要权限或会实质改变结果的用户选择，才带明确影响来询问。不能要求钧钧自行判断故障属于哪个模块。

第2.4节的衔接由当前赛事与单场准备负责到底；版本、画像和TK的读取、修改与读回由知识与数据复用原业务能力承接，周期解释与单场预案留在原位置。日报与自动化消费修订后的成果，不单独维护用户认识。

第2.5节的统一入口、视角清单及页面/对话接线同样由当前赛事与单场准备负责，不新增第四个主责模块；新增视角的内容和方法仍复用各自原能力。

## 8. 实施顺序与每步交付

对应SSD已实施，并按钧钧当次“你执行／全部完成”的授权接回正式入口；实际可读内容、验证范围与未完成项以SSD第8.2节为准。后续未另行授权的工程仍默认由小白承接，沿用原SSD和原进度，不另开同义方案或维护后台。

| 顺序 | 实际工作 | 必须交付的结果 | 不算完成 |
|---|---|---|---|
| 1 | 按第3、4节核对当前内容、入口和重复链；修订原SSD | 明确逐项保留、共享、合并、补齐、退出范围，以及正源、责任和具体文件接点；保留旧实现证据 | 再造一张用户待办表，或要求用户选择方法 |
| 2 | 先整理 S16 有效内容，修供给断点、补参赛队和实际版本、筛存量与新增分析 | 从原入口读到当前可用的赛事与队伍内容；未解决项有实际补查和责任 | 只有采集器、占位字段、来源链接和覆盖状态 |
| 3 | 合并公共准备与重复分析，接通原阅读入口、第2.4节对应内容和第2.5节可见判断入口 | 打开比赛即可阅读；主动判断时看得到可用视角，选择即进入相关内容，改后更新受影响分析；不靠用户记名称 | 仅加总入口或方法介绍、改名称，把旧长文折叠，或只加一个无内容关联的个人笔记框 |
| 4 | 接回原排程、简报、日报及变化更新，按授权启用 | 真实无人点开也会提前准备，多个入口同源，关键变化可及时读到 | CLI可以跑但无人自动调用，或只日报发布成功 |
| 5 | 以正在进行的 S16 连续验证并修正 | 达到第9节内容、合并、时效和省力验收；保留回退点 | 单元测试通过、赛后补稿或历史回放冒充赛前 |

可以为效率并行处理独立供给，但不能绕过现有内容盘点，先建一套新底座。共享核心、正式写入与生产激活须单线管理。

## 9. 验收：看内容和实际使用，不只看程序

| 验收项 | 必须观察到的结果 |
|---|---|
| S16内容覆盖 | 对当时官方已确认的参赛对象逐项核对第3.2节适用内容；未进入已有对阵的队伍也有准备。不存在无人负责的空项，未解决项不伪装已齐 |
| 内容质量 | 抽查正文或字幕与输出，观点忠于原文；能读到有实质论据的作者分析，而非仅报道背景。不存在伪造填充、旧名单或不适用旧知识 |
| 合并真实发生 | 至少证明重复画像/三维只有一处维护、相同取数/分析有共享实现、对话/页面/日报不各自产一套；有旧入口处理和回归结果 |
| 无需记名称 | 正式小雪新会话用用户自然表达走到成果；不要求方法名、工具名、选视角或回复“继续”才准备 |
| 个人判断可选 | 全程只读、不填写、不回复也能取得内容和小雪分析；系统不创建用户已确认判断，不把未做判断算失败 |
| 个人判断有对应内容 | 分别验证第2.4节五项：从本场分析能找到实际使用的内容与依据，并通过自然表达或页面衔接进入对应原能力，不要求用户记方法名；不存在的认可内容不伪造 |
| 统一入口可见且可进入 | 不熟悉名称的用户能在原当前赛事页发现可选视角，知道各项能做什么；选择后直接带入对象、已有内容和依据，不只显示说明或要求复制口令；未选比赛时仍可进入适用的赛事/队伍判断 |
| 视角可以继续增加 | 用隔离登记与回读验证：新增一个已具备能力的视角后，页面和对话读取同一清单并能进入，不因固定五项限制失败，不需要新页面、新口令或平行资料库；移除测试项不影响原有入口 |
| 讨论与写入归属 | 临时想法不覆盖长期内容；明确修正版本、某队画像或某条TK时只写对应原内容并读回；周期解释不改TS数值，本场采用不自动成为长期认可，预案不冒充交易执行 |
| 修改后的关联更新 | 用一次正式认识修订验证：依赖它的当前分析更新，无关分析不重算；原用户判断、冻结日报和历史快照保持原样，未确认修订不冒充正式认识 |
| 方法有实际应用 | 输入与正式方法可追溯，推导实际产生；同一证据不重复计票，重要分歧保留；不适用时不硬套、不强造方向 |
| 阅读效率 | 一场相关内容集中可读；相同事实不重复，来源按需展开，再次阅读突出变化。执行方核查关键观点和反证未因压缩丢失，不以字数下降单独判通过 |
| 连续赛前时效 | 连续3场真实S16已确定对阵，在用户未打开、未催促时产生赛前可读成果；提前已确定者满足赛前90分钟目标，晚确定者记录实际时延；赛后补稿不计 |
| 改期与来源故障 | 检查跨日、改期、正文受限及模型失败，其他内容照常可读，有有限恢复和工程接手；不转交用户搜索 |
| 用户与历史保护 | 更新不覆盖原话、预案和未保存输入；回放不读取未来信息，旧日报冻结不变；原入口和独立纯阵容能力不被误伤 |
| 真实上线 | 原工作台、正式小雪对话和获授权的原自动化路径读到同源结果；测试环境、文件存在、日志上传和发布成功不代替此项 |

执行方在同一赛前截止点独立核对约定来源的漏收、误筛、过时输入和错误推导，不能让钧钧重新全网搜索来充当测试员。正式上线或三场验证尚未完成时，必须保留“未完成”的总目标状态。

不承诺全网零遗漏、任何时候绝对无信息差、分析必对或盈利。承诺的是约定范围内认真准备、持续更新、诚实呈现限制，并由系统承担搜索、整理和恢复工作。

## 10. 不做什么，以及文档怎样接续

- 不新增需要用户记住的业务名称、独立报告、第二知识库或平行MCP Server，不把方法目录改成必走流程。

- [总体设计](交易信息系统-总体设计.md)继续定义产品骨架；本文是赛前内容整合与自动准备的范围展开，不改整个项目目的。
