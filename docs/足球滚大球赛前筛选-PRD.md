# 足球观察台 — 产品需求

> 2026-10-22｜小雪工作台的足球模块
> 产品总纲：[交易信息系统](交易信息系统-总体设计.md)；实现规格：[足球 SSD](足球滚大球赛前筛选-SSD.md)。本文承接本次已确认的使用方案，取代旧 idea 中的功能范围。

## 1. 有什么

进入小雪的「足球」，看到已经准备好的比赛清单：哪些适合关注上半场破蛋，哪些适合留到75分钟后观察，以及每场保留或排除的依据。比赛开场后继续留在页面，临时想看一场也能找到。当前按本节默认口径产生候选，后续只调整规则参数和事实范围，不改页面结构。

系统负责赛程、赛前资料、筛选和保留资料；钧钧看清单、自己看滚球盘口，需要时记一句交易TK。日常使用没有额外整理任务。

| 功能 | 打开后看到什么 |
|---|---|
| 默认观察清单 | 尚未结束的候选，以及未来24小时候选；已开赛在前、待开赛按时间排列 |
| 两种玩法 | 「全部 / 半破 / 75分钟后」切换，同一场可以适合其中一种或两种 |
| 比赛详情 | 历史对赛、双方近期主客场表现、进球时间资料、已核实阵容，以及两种玩法各自的理由 |
| 全部比赛 | 搜队伍或联赛，查看已排除和资料待补场次，开赛后仍能找到 |
| 最近结束 | 收起展示最近7天已结束比赛，查看当时资料和交易TK |
| 一句话交易TK | 自动带入比赛和玩法，写一句后保存；从原比赛和足球TK分类找回 |

24小时是默认时间窗口。联赛覆盖按实际资料来源展示，页面同时显示覆盖范围和最近成功更新时间。

## 2. 日常怎么用

1. 打开「足球」，直接看候选和保留理由。
2. 想看半破就切「半破」；想晚些看就切「75分钟后」。展开某场，先看两三条关键事实，再按需看完整资料。
3. 比赛开始后，清单和理由仍在。自己到盘口页面看当时情况，回到小雪不用重新找资料。
4. 有交易认识时，点「记交易TK」，补一句并保存。没有要记的就直接离开。

第一次到75分钟才打开页面，也应能读取后台提前准备的内容。没有提前准备记录时，仍能找到赛程和实际取得的资料；开赛后取得的内容标明「开赛后补充资料」。

## 3. 页面

### 列表

顶部是玩法切换、搜索、更新时间和刷新。默认区域为候选；「全部比赛」「最近结束」收在下方。

每场显示：

- 联赛、双方队名、北京时间日期和开球时间、比赛状态。
- 半破和75分钟后的玩法标签。
- 有可靠记录时显示真实初盘。
- 两三条具体理由，例如「最近一次交手上半场有球」，同时给出是哪场、什么比分；不用泛泛的“进攻较强”代替资料。
- 「查看详情」「记交易TK」。

「全部」中同一场只占一行。半破排除、75分钟后保留时，仍出现在候选中，突出保留的玩法；详情可查看另一玩法的排除原因。

### 详情

先显示比赛和每种玩法的筛选结果，再显示支撑事实。双方近期资料按主场、客场分清，历史交手与球队近况分清；首发和预计阵容分清。

理由旁可展开原始比赛、资料出处和时间。无资料的字段写清缺哪项；不要求用户补录。

### 阅读体验

电脑端紧凑展示，手机端单列阅读。刷新、切换详情再返回时保留搜索、玩法、展开项和阅读位置。后台更新不突然移走正在阅读的比赛，新变化提示后再更新列表。

## 4. 当前默认筛选办法

这是先能直接运行的默认口径，不打分、不算概率。系统只做赛前资料筛选；第25分钟、半场和75分钟的盘口/比赛数据由钧钧临场自己核验。

### 上半场破蛋

1. 圈池：真实初盘总进球 `2.5` 或 `2.75`，或者主客队命中指定球队名单。
2. 排除：真实初盘 `3` 或以上；指定名单不能绕过这一层。
3. 事实支持：最近一次交手有上半场进球，或主队最近两场主场、客队最近两场客场有上半场进球。系统列出样本，不再执行无法提供的“五项至少四项”。
4. 阵容：已核实首发且为 `442/451/460/541/550` 时排除；已核实为 `433/334/4321` 时保留；其他阵型或首发未出不自动排除，标记待临场核验。
5. 结果：未命中赛前排除层即进入半破观察清单。第25分钟盘口和半场角球/射门是清单上的临场复核提示，不因系统拿不到而把比赛归零。

### 75分钟后大球

1. 圈池：真实初盘总进球 `2.5` 或以上，或者主客队命中指定球队名单。
2. 排除：初盘低于 `2.5` 且不在名单；双方最近5场均没有明确的75分钟后进球/失球支撑；已核实为明显防守阵型且没有攻击型替补选项。
3. 保留：初盘达到圈池条件，并且至少有一条具体晚段支撑：任一队最近5场有至少2场在75分钟后进球或失球，或双方最近5场合计有至少3场在75分钟后出现进球；阵容未公布不因缺失直接排除。
4. 结果：进入“75分钟后观察”不代表现在下注。75分钟时再由钧钧看比分、盘口和水位；`0-0且半球`作为绝杀候选单独标记，80分钟后的大小球水位按用户原规则手动判断。

两种玩法各自计算，同一比赛可以一边保留、一边排除。历史样本不足时显示资料待补，不把零样本当成“没有进球”。

## 5. 筛选结果

每种玩法独立给出「保留 / 排除」，排除时展示首个触发层及对应事实；资料不足时附加「资料待补」状态，不把缺失当成排除，也不把待补场次混入候选。

资料是否齐全另行显示，不混入二元结果：

| 实际情况 | 页面表现 |
|---|---|
| 已有足够资料支持保留 | 进入对应玩法的候选清单 |
| 已触发明确排除条件 | 在全部比赛中显示「排除」和原因 |
| 缺少决定结果所必需的资料 | 在全部比赛中显示「资料待补」；不伪造保留或排除 |
| 只有非必需资料缺失 | 保留已完成的筛选结果，说明具体缺项 |
| 更新失败但有上次结果 | 继续显示上次有效资料和时间，提示更新未成功 |
| 成功筛完，确实无人保留 | 显示「无候选」 |
| 没有已确认候选，但还有待补场次 | 显示「暂无已确认候选，部分比赛资料待补」 |

赛前资料支持什么条件，就检查什么条件。两种玩法的赛前筛选与用户赛中看盘口的动作分开，赛中盘口不会成为生成赛前清单的前提。具体方法的可执行范围见SSD规则表，后续方法讨论沿该表更新。

## 6. 比赛和资料一直找得到

后台按赛程提前准备，不依赖用户访问页面。比赛开球、跨日、页面刷新、服务重启，都不清空已有资料和理由，也不要求先收藏。

开赛前可更新资料；开赛后保留最后有效的赛前版本，后补资料单独展示。赛果不会反向改写赛前理由。后续修改筛选规则，也不悄悄改写已开赛比赛的历史结果。

已开赛但未结束的比赛持续可见，不因超过默认未来24小时窗口而消失。最近结束的默认查看范围是7天，这只是页面范围，不是到期删除记录。

有可靠状态才显示「进行中」或「已结束」。只知道计划开球时间时显示「状态待更新」，不按时钟猜比赛分钟，也不按开球后90分钟自动结束。

延期、改期、取消各有状态。改开球时间、改队名或换来源后仍关联原场比赛、原资料和原TK；身份不能确定时不自动合并。

## 7. 交易TK

从比赛点「记交易TK」，自动带入足球、对阵、日期和当前玩法。钧钧写一句正文即可保存，允许修改带入的内容。

保存后在该场详情和现有交易TK中可查，刷新后仍在；重复点击保存不会生成重复条目。未保存的文字返回后可继续编辑。

## 8. 验收时看这些

| 使用场景 | 必须看到的结果 |
|---|---|
| 开赛前没打开，到75分钟才进来 | 找到该场和已准备的赛前资料 |
| 比赛跨过北京时间零点 | 原比赛、理由和TK仍可找回 |
| 刷新页面、重启服务 | 已有准备记录不丢失 |
| 初盘或首发缺失 | 明确缺项；不因为空字段而整批排除 |
| 来源暂时失败 | 保留上次成功内容和时间，错误不冒充无候选 |
| 两种玩法结果不同 | 一场只占一行，各自结果和理由清楚 |
| 比赛延期、改名 | 原场身份和TK不丢、不重复 |
| 保存一句足球TK，再重新打开 | 原比赛和足球分类均能找回同一条 |
| 手机查看详情后返回 | 页面可读，位置和筛选保留 |
